# 事故录音转写 · 敏感短语遮蔽预览

披露专员在事故录音转写稿公开前，需要遮蔽数万条敏感短语。本项目是一个
纯前端 React 单页应用：载入 `{ text, patterns }` JSON，以 **Aho-Corasick
多模式匹配 + 线性覆盖并集** 实时生成 `#` 遮蔽预览，支持短语的增改、启停、
删除，可放弃改动或采纳为下载稿后继续调整。

> 大量短语彼此嵌套、交叠时，逐词搜索（每词全文字符串搜索）会冻结页面，
> 朴素区间标记还会因命中重叠漏掉或重复计算字符。本实现的耗时**不随命中数
> 增长**：自动机扫描每代码单元 O(1)（摊销），覆盖并集两遍线性扫描，不为
> 每个命中分配任何对象。

## 输入文件格式

JSON 根对象**必须且仅含**两个键：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `text` | string | 最多 **2,000,000 个 UTF-16 代码单元**；只允许换行 `U+000A` 与可打印 ASCII `U+0020..U+007E` |
| `patterns` | string[] | 1..50,000 个**互不重复**字符串；每项长 1..200，字符集同可打印 ASCII（**不含换行**）；总长 ≤ 300,000 |

任何不满足上述约束的文件（含 JSON 解析失败、多余键、重复短语、越界长度、
非法字符等）都使页面显示 **`INVALID_INPUT`** 并**清除当前会话**
（原文、工作集、已采纳稿全部清空，需重新载入合法文件）。

示例见 [`sample-input.json`](./sample-input.json)。

## 代码单元语义（固定约定）

1. 一切长度与索引都以 **UTF-16 代码单元**为准（即 JavaScript 字符串的
   `.length` 与下标），不是 Unicode 码位，也不是字节。
2. 合法字符集仅含 `U+000A` 与 `U+0020..U+007E`，它们在 UTF-16 中全部
   **恰好占一个代码单元**，因此在合法输入上“代码单元数 = 字符数”。
   代理项（surrogate，即超出 BMP 的字符如 emoji）、TAB/CR 等控制字符、
   非 ASCII 字符一律不得出现，出现即判非法输入。
3. **匹配区分大小写**：`Abc` 与 `abc` 是不同短语。
4. **匹配不跨换行**：换行只允许出现在 `text` 中，短语不含换行；扫描器在
   每个换行处将匹配状态重置为自动机根状态，任何短语都不可能匹配跨越换行
   的内容。换行本身永远原样保留（不会变成 `#`）。
5. 属于**任意短语的任意完整匹配**的代码单元一律替换为 `#`；多个匹配
   交叠、嵌套、相邻时，取所有匹配区间的**覆盖并集**——不遗漏任何被覆盖
   位置，也不重复计数。其余代码单元**原位保留**（包括空格、标点、换行）。
   输出与输入的代码单元数始终相等。
6. 每次短语增改、启停、删除后，预览都**从原文完整重算**，不做增量修补、
   不复用上一次的遮蔽结果。

## 短语编辑与错误码

- 新增或修改时若值为**空串、与现有短语重复（区分大小写）、长度越界、
  含非法字符（如换行/TAB）**，显示 **`INVALID_PATTERN`**，输入框保留
  当前值便于继续修改；工作短语集与**已采纳稿均不被覆盖**。
- 对越界下标的修改/启停/删除同样报 `INVALID_PATTERN`。
- **放弃**：把工作短语集回滚到已采纳稿（未采纳过时回滚到文件载入态）。
- **采纳为下载稿**：把当前预览与其短语集快照固化。采纳之后继续调整短语
  不会改变已采纳稿；再次采纳才更新。
- **下载**：下载文件就是屏幕上“已采纳的下载稿”区域所示的同一字符串，
  UTF-8、无 BOM，逐字符一致（采用 `Blob` 由该字符串直接生成，不经任何转换）。

## 性能

- 满规模（text 2,000,000 代码单元、约 1,700 条启用短语、密集重叠命中）
  在参考环境上重算约 1 秒以内；验收门槛为 **3 秒**（见
  `src/core/masker.test.ts`）。
- 自动机记忆化“完成转移”：任何 `(状态, 字符)` 的失败链行走至多发生一次，
  构建与扫描均为线性摊销；补写条目数有界。
- 结果代码单元以 `Uint16Array` 持有，并按 32K 分块 `String.fromCharCode`
  生成字符串，避免巨型参数列表；额外内存 O(|text|)。

## 本地开发

```bash
npm install
npm test        # Vitest：朴素预言机对照、高重叠长文本、3 秒时限、校验
npm run dev     # 本地开发
npm run build   # tsc 类型检查 + Vite 产出 dist/
npm run preview # 预览构建产物
```

## Docker / Docker Compose

```bash
# 构建并发布页面，宿主端口可用 WEB_PORT 覆盖（默认 8080）
WEB_PORT=9090 docker compose up --build

# 一次性验收服务（运行 Vitest，退出码即结果）
docker compose --profile verify run --rm verify
```

也可直接构建镜像：

```bash
docker build -t transcript-redactor .
docker run --rm -p 8080:80 transcript-redactor
```

镜像为多阶段构建：构建阶段先执行 `npm test`（验收失败则镜像构建失败），
再 `npm run build`；运行阶段为 nginx 纯静态托管。

## 测试方法说明（不使用固定结果）

测试**不内置任何遮蔽结果的黄金文件或写死的预期串**：所有遮蔽预期均由一个
与生产实现无关的**朴素预言机**在运行时生成——对每条短语用 `indexOf`
逐位置枚举全部完整匹配（允许重叠），用区间差分求覆盖并集后产出 `#` 串，
再与 AC 实现的输出逐字符比对。随机数据由固定种子的伪随机生成器产生
（可复现，而非固定结果），覆盖随机文本、深嵌套（1..120 条同前缀游程）、
高重叠长文本、换行边界、大小写区分、空文本等场景。
